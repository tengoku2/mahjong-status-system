# mjs 拡張ルール整理

作成日: 2026-06-24

## 1. 目的

この文書は、mjs で扱う通常戦・大会戦・東風戦・特別点の管理方針を整理する。

大会規約そのものではなく、mjs がどの単位で対局を保存し、どの単位で集計するかを定義する。

## 2. 基本方針

- 現行 mjs の機能は維持する
- 4人半荘、3人半荘、4人東風、3人東風はそれぞれ独立して集計する
- 通常戦と大会戦は分けて集計する
- 大会名・イベント名が同じ対局は、同じイベントとして集計できるようにする
- トーナメント表、勝ち上がり、リーグの対戦管理は mjs では行わない
- 2半荘単位、10半荘単位などの大会進行は、人間側で管理する
- mjs は対局結果、イベント別ランキング、個人成績、補正点を扱う
- Event未指定の通常表示・通常集計では、種別に対応する標準Eventを対象にする
- 旧データや検証データのように Event が未設定の対局は、v2の通常集計には混ぜない
- 旧 `tournament_name` を明示指定した場合は、互換用として Event 未設定の旧データも検索対象にできる

## 2.1 補正点

補正点は Event 単位で管理する。

用途は、運営判断による手動加点・減点、特殊裁定、後から反映する特別点などを想定する。

```text
対象: Event + ユーザー + 対局種別
入力: 補正ポイント、理由
反映先: Event別ランキング
削除: 物理削除ではなく無効化
```

補正点は対局結果そのものを変更しない。
ランキング表示時に、対局ポイントへ補正点を加算して表示する。

## 3. 対局種別

mjs では、以下を別種別として扱う。

```text
4人半荘
3人半荘
4人東風
3人東風
```

半荘と東風は混ぜて集計しない。
ただし、統計データとしては東風戦も保存し、将来的に東風専用ランキングや東風専用スタッツを表示できるようにする。

## 4. 通常戦ルール

通常戦は、白鳳会 竹鳳季26シーズンルールをベースにする。
ただし、借金点、役満ボーナス、MVPレースは採用しない。

### 4.1 通常戦 4人半荘

```text
対局種別: 4人半荘
原点: 25,000点
返し: 30,000点
ウマ: +50 / +10 / -10 / -30
同点処理: 起家取り
西入: あり
集計: 4人半荘ランキングとして独立
```

ポイント計算:

```text
基本点 = (最終持ち点 - 30,000) / 1,000
最終ポイント = 基本点 + ウマ
```

### 4.2 通常戦 3人半荘

```text
対局種別: 3人半荘
原点: 35,000点
返し: 35,000点
ウマ: +15 / 0 / -15
同点処理: 起家取り
西入: あり
集計: 3人半荘ランキングとして独立
```

ポイント計算:

```text
基本点 = (最終持ち点 - 35,000) / 1,000
最終ポイント = 基本点 + ウマ
```

### 4.3 通常戦 東風

東風戦は、半荘とは別の統計データとして保存する。

通常戦の東風は以下の扱いにする。

```text
対局種別: 4人東風
原点: 25,000点
返し: 30,000点
ウマ: +20 / +5 / -5 / -20
同点処理: 起家取り
飛び終了: あり
アガリやめ: あり
延長: 南入まで
集計: 半荘とは別集計
```

ポイント計算:

```text
基本点 = (最終持ち点 - 30,000) / 1,000
最終ポイント = 基本点 + ウマ
```

```text
対局種別: 3人東風
原点: 35,000点
返し: 35,000点
ウマ: +5 / 0 / -5
同点処理: 起家取り
飛び終了: あり
アガリやめ: あり
延長: 南入まで
集計: 半荘とは別集計
```

ポイント計算:

```text
基本点 = (最終持ち点 - 35,000) / 1,000
最終ポイント = 基本点 + ウマ
```

半荘と東風は混ぜて集計しない。
東風専用ランキング、東風専用履歴、東風専用スタッツとして扱う。

## 5. 大会戦ルール

大会戦は、基本的に二盃口トーナメント レギュレーションに準拠する。
ただし、mjs は大会進行そのものを管理しない。

### 5.1 大会戦 4人半荘

```text
対局種別: 4人半荘
原点: 25,000点
返し: 30,000点
ウマ: +50 / +10 / -10 / -30
飛び終了: なし
アガリやめ: なし
西入: なし
同点処理: 順位点を分配
集計: 大会名・イベント名ごとに集計
```

ポイント計算:

```text
基本点 = (最終持ち点 - 30,000) / 1,000
最終ポイント = 基本点 + 順位点
```

同点時は起家取りを行わず、同点者の対象順位点を合算して等分する。
3人以上が同点で順位点を割り切れない場合は、座席が起家に近い順に端数を配分する。
大会戦では順位決定のための起家取りは行わないが、端数配分のために座席順を使用する。

### 5.2 大会進行の扱い

mjs では以下を扱わない。

- トーナメント表
- 勝ち上がり判定
- 2半荘で1セットという固定管理
- 10半荘リーグなどの試合数固定管理
- 対戦カード管理

mjs は、同じ大会名・イベント名で登録された対局をまとめて集計できればよい。
これにより、2半荘トーナメント、10半荘リーグ、その他の形式へ手動運用で対応できるようにする。

### 5.3 大会戦 3人戦

大会戦の3人戦は現時点では未確定とする。
将来必要になった場合に備えて、RuleSet と Event の構造上は拡張可能にしておく。

## 6. 同点処理

同点処理は RuleSet ごとに設定する。

```text
seat_order: 起家取りで順位確定
split_uma: 順位点を分配
```

通常戦:

```text
seat_order
```

大会戦:

```text
split_uma
```

`seat_order` を使う場合、Bot または外部入力側は、起家からの座席順を持つ必要がある。
`split_uma` を使う場合、同点者の対象順位点を分配してポイントを計算する。
3人以上が同点で端数が出る場合は、座席が起家に近い順に端数を配分する。

## 7. 西入

西入は RuleSet ごとに設定する。

```text
allow_west_round: true / false
```

通常戦:

```text
allow_west_round = true
```

通常戦の半荘では西入ありを基本とする。
通常戦の東風では西入せず、南入までとする。
通常戦では、飛び終了あり、アガリやめありを基本とする。
飛び終了は、持ち点が0点未満になった場合に成立する。
0点ちょうどは飛び終了にしない。
アガリやめの具体的な挙動は TANKI 側の設定に従い、mjs は最終結果を受け取って集計する。

大会戦:

```text
allow_west_round = false
```

大会戦では、飛び終了なし、アガリやめなしを基本とする。

将来、別イベントで西入あり・なしを切り替えられるようにする。

## 8. 特別点

借金点、役満ボーナス、MVP合算ランキングは採用しない。

特別点として残すのは、管理者が手動で入力する補正点のみとする。

用途:

- ペナルティ
- 運営判断による補正
- 記録ミス修正
- その他、対局結果に直接依存しない加点・減点

補正点は、4人半荘、3人半荘、4人東風、3人東風で独立管理する。
異なる対局種別の補正点を合算しない。

想定データ:

```ts
Adjustment {
  adjustment_id: string
  guild_id: string
  user_id: string
  event_id?: string
  game_type: "4p_hanchan" | "3p_hanchan" | "4p_tonpu" | "3p_tonpu"
  amount: number
  reason: string
  created_by: string
  created_at: datetime
}
```

## 9. Event / RuleSet の考え方

### 9.1 RuleSet

RuleSet は点数計算と対局挙動のルールを表す。

持つべき項目:

- 対局種別
- 原点
- 返し
- ウマ
- 飛び終了あり・なし
- アガリやめあり・なし
- 西入あり・なし
- 同点処理

### 9.2 Event

Event は大会、リーグ、通常会などのまとまりを表す。

持つべき項目:

- イベント名
- イベント種別
- 使用 RuleSet
- 開始日
- 終了日
- 状態

同じ Event に紐づく対局は、イベント別ランキングとして集計できる。

## 10. mjs の責務

mjs が行うこと:

- 対局結果を保存する
- ルールに応じてポイントを計算する
- 通常戦と大会戦を分けて集計する
- 4人半荘、3人半荘、4人東風、3人東風を分けて集計する
- イベント名・大会名ごとのランキングを表示する
- 手動補正点を保存・反映する
- 局単位スタッツを保存・表示する

mjs が行わないこと:

- 大会の勝ち上がり判定
- トーナメント表の管理
- リーグ戦の組み合わせ管理
- 大会参加可否の判定
- CPU代理の扱い
- 借金点の計算
- 役満ボーナスの計算
- MVPレース用の合算ランキング
